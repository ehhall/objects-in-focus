# The dataset

100 real-world scenes with every object segmented by hand. Fifty indoor, fifty
outdoor. Segmented at full resolution (1024 × 768) in CVAT, with objects of
the same category given the same label within a scene.

| | |
|---|---|
| Scenes | 100 |
| Annotated polygons | 2,870 |
| Objects (excluding background surfaces) | 2,509 |
| Objects carrying an id in `masks/` | 2,427 |
| Distinct object labels | 359 |
| Objects per scene | 24 on average (range 4–70) |
| Objects flagged occluded | 41% |
| Mean visible fraction of an object's outline | 0.86 |
| Image size | 1024 × 768 |

Labels come from the ConceptNet vocabulary, so they connect to semantic
resources rather than being free text. Eye-movement data for these scenes was
collected at the UC Davis Visual Cognition Lab: 100 participants, 12 seconds
per scene.

## Folder by folder

### `images/` — the scenes

`target_<scene>.png`, 1024 × 768, RGB. The scene name is everything before
the extension and is the key for every other folder.

```python
scene.image      # (768, 1024, 3) uint8
```

Two files are capitalised inconsistently relative to `annotations/`
(`target_AtticStorage`, `target_atticRoom`). The package resolves paths
case-insensitively; build paths by hand and you will hit it.

### `annotations/` — the polygons

`target_<scene>.xml`, CVAT 1.1 export. One `<polygon>` per annotated object:

```xml
<polygon label="coral" points="126.09,524.34;118.59,537.23;..."
         occluded="0" z_order="23"/>
```

- `label` — the category, as typed by the annotator
- `points` — `x,y` vertices separated by `;`, in image pixels, not closed
- `occluded` — 1 if another object partly hides this one
- `z_order` — CVAT drawing order. Not used for depth sorting; see below.

```python
from oif import read_annotation
ann = read_annotation("annotations/target_bakery.xml")
ann.objects()      # polygons, minus background surfaces
ann.background()   # the surfaces themselves
```

Eleven labels are treated as background surfaces rather than objects: floor,
sky, wall, grass, carpet, ground, ceiling, trees, water, road, pavement. That
list is `oif.BACKGROUND_LABELS`, and every function that uses it takes a
`background=` argument if you want a different one.

### `masks/` — the label maps

`target_<scene>.npy`, int32, shape (768, 1024). `mask[y, x]` is the id of the
object visible at that pixel; 0 means no annotated object.

```python
scene.label_map              # (768, 1024) int32
scene.label_map == 7         # boolean mask of object 7
scene.labels[7]              # 'bread'
```

Ids are unique **within** a scene, not across scenes: id 7 in the bakery and
id 7 in the beach are unrelated objects. Ids are not always contiguous — a gap
means an object was completely hidden by nearer ones when the map was painted.

Objects are painted **back to front**: the farthest object goes down first and
nearer objects paint over it, so the object that owns a pixel is the one
nearest the viewer. Objects the annotator flagged as `occluded` are painted
before unoccluded ones regardless of their depth score, so an object cannot
end up sitting on top of the thing that hides it.

**Nine mask files in the published release are truncated** (2 bytes):
campsite, canal, canyon, casino, castle, cemetery, church, city, classroom.
`oif repair` rebuilds them; `scene.label_map` rebuilds in memory even if you
do not.

### `depth/` — monocular depth

`target_<scene>_disp.npy`, float32, shape (1, 1, 320, 1024) — raw MonoDepth2
(Godard et al., 2019) output, i.e. *disparity*, where larger means nearer.

`oif.depth.load_depth` squeezes it, resizes 320 → 768 rows, flips the sense so
larger means **farther**, and rescales to [0, 1]:

```python
scene.depth                                   # (768, 1024), 0 near, 1 far
load_depth(path, invert=False, rescale=False) # raw disparity, untouched
```

It is relative depth, not metres. Useful for ordering objects front to back
and as a regression predictor; not a claim about absolute distance.

### `derived/` — written by the package

- `labels.csv` — `image, mask_id, label, occluded, polygon_index, area,
  visible_fraction, match_score, rebuilt`. The lookup from mask id to object.
  Generated by `oif labels`; see [labels.md](labels.md).
- `rebuilt_labels.csv` — what `oif repair` painted into each id, for the
  scenes it rebuilt.
- `objects.csv` — per-object features and fixation counts, if you ran
  `oif objects`.

Everything here is reproducible from the source data. Delete it and
regenerate at will.

### `raw/` — the fixations

One file per scene, `target_<scene>_memorize.npy`: a 768 × 1024 float array
with a 1 at every pixel where a fixation landed while viewers memorized the
scene, pooled over viewers. `scene.fixation_map()` loads the array;
`scene.fixations()` and `data.fixations()` turn it into the canonical table.
Pooled maps carry no viewer identity, order or durations, so those columns
come back empty.

Your own eye-tracker exports can go in the same folder — `data.fixations()`
reads both formats side by side. The canonical schema is:

| column | meaning |
|---|---|
| `subject` | viewer id |
| `image` | scene name, matching `images/` without the extension |
| `fix_index` | 1-based fixation number within a trial |
| `x`, `y` | position in image pixels, origin top-left |
| `duration` | milliseconds |
| `task` | viewing task, if the study had more than one |

SR Research DataViewer exports and the lab's older `locs_1`/`locs_2`/`durs`
layout are recognised automatically. Anything else: pass `columns={...}`.

Fixation data for the COCO-Freeview scenes is public — see
[Chen et al., 2022](https://openaccess.thecvf.com/content/CVPR2022W/EPIC/html/Chen_Characterizing_Target-Absent_Human_Attention_CVPRW_2022_paper.html).

### `figures/`, `papers/`, `notebooks/`

Figures from the paper and from this package, the paper and ICCV 2025 poster,
and the notebooks — the tutorial plus the original analysis notebooks, kept
for provenance. The analysis notebooks were written against Google Drive
paths and will not run as-is; the package is the maintained version of what
they do.

## Coordinate conventions, in one place

- Images and label maps are **(height, width)** = (768, 1024) arrays.
- Fixation `x` is the column, `y` is the row: `label_map[y, x]`.
- The origin is the **top-left** corner.
- Eccentricity is measured in pixels from the centre of the image.
- Depth is 0 near, 1 far, after `load_depth` defaults.
