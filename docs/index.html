What was this person looking at?

An eye-tracker tells you where someone looked — an x and a y. Research on attention usually needs the other answer: what they looked at. 100 real-world scenes with every object segmented by hand, and the tools to get from one answer to the other.

Everything is segmented, not just the foreground

Each scene was outlined polygon by polygon in CVAT at full resolution — 2,870 polygons in total, labelled from the ConceptNet vocabulary rather than a fixed category list. When a fixation lands somewhere, there is an annotated object under it.

Every scene also carries a monocular depth map. Objects are painted into the label map back to front, so the one that wins an overlap is the one nearest the viewer — the thing they actually saw.

  • Hand-drawn polygons with occlusion flags, exported from CVAT
  • Integer label maps: mask[y, x] is the object at that pixel
  • MonoDepth2 depth for every scene

Depth decides who wins an overlap

A chair in front of a table shares pixels with it. Without a depth order, whichever polygon was drawn last takes them — and fixations get attributed to an object hidden behind another one.

Objects the annotator flagged as occluded are painted first regardless of their depth score, so an object can never end up sitting on top of the thing that hides it.

Where attention goes

Figures from Hall & Loh, ICCV 2025 HiCV

Objects are everywhere. Fixations are not.

Pile up every object across all 100 scenes and you get a broad, textured band across the middle of the frame. Pile up every fixation and you get one bright blob in the centre.

That gap is the problem the model has to explain: objects are distributed one way, attention another. Size and position account for much of the difference — but not all of it, and the leftover is where meaning lives.

Predicted, observed, and the gap between

Four numbers about an object — its size, how far it sits from the centre, how far away it is, and how salient — predict how many fixations it collects. On these scenes that model explains 82% of the variance in cumulative fixations per object.

Reading down each column: the scene, the model's prediction per object, what viewers actually did, the absolute residual, and the classic Gaussian fixation density map. The residual row is the interesting one — objects that pulled far more attention than their geometry can account for.

Rows: prediction · true · residual · density

Attention, redrawn as objects

The usual fixation heatmap is a blur over pixels. Fill each segmented object with the attention it received instead and the map becomes a statement about things rather than places — this sofa, that window — which is what a theory of object-based attention actually needs.

What the model weighs, and where it breaks

Size carries the most weight. Eccentricity and depth both pull negative: central and nearer objects attract more fixations.

Trained on OiF the model reaches R² = 0.82; on COCO-Freeview, 0.66; pooled across both without a dataset term it falls to 0.49. Viewpoint, viewers per image and retinal object size differ between the sets, and the model feels it. That failure to generalise is the paper's real finding.

Learn it in a browser tab

No installation · about five minutes

The Colab tutorial installs the package, downloads a handful of scenes and walks through the whole path — open a scene, look at its objects, map fixations onto them, build a table, fit the model — with a picture at every step.

If you have never written Python, this is the place to start. Press the play buttons in order.

Open the tutorial in Colab 
# the line this whole package exists for
from oif import OiF

data  = OiF()
scene = data["target_kitchen_IDS01"]

looked_at = scene.map_fixations(
    data.fixations(),
    method="disc", radius=25,
)

Get it

Python 3.9+ · MIT code · CC BY 4.0 data 
git clone https://github.com/ehhall/objects-in-focus.git
cd objects-in-focus
pip install -e ".[full]"

oif check      # is my copy of the data complete?
oif labels     # what each mask id is
oif repair     # rebuild files that shipped truncated
oif objects --fixations raw/ --out objects.csv

Bring your own fixations

Drop your eye-tracker's CSV exports into raw/. SR Research DataViewer exports are recognised without being told; anything else takes one columns={…} argument. Whatever goes in, the same tidy table comes out.

The package also fixes what the original release could not: it recovers what every mask id actually is — the release shipped none — and rebuilds nine mask files that were uploaded truncated.
